# trade-settlement-recon

The daily checks an operations team at a small broker runs before the day is closed: do our trades match the broker's confirmations, is client money covered, and which client movements need an AML review. The output is an Excel workbook that a person can read, filter and sign off.

## What it checks

1. **Trade reconciliation** (`recon/match.py`). Matches internal trades with broker confirmations by trade id and classifies every break: missing_at_broker, missing_internal, quantity_mismatch, price_mismatch (tolerance 100 ore) and duplicate.
2. **Client money** (`recon/client_money.py`). What clients are owed must be covered by the segregated bank balance. A gap below zero is a SHORTFALL.
3. **AML alerts** (`recon/aml.py`). Five readable rules with a reason on every alert: LARGE_MOVEMENT, HIGH_RISK_COUNTRY, STRUCTURING (three or more deposits just under the large limit within 24 hours), PASS_THROUGH (a large deposit mostly withdrawn within 48 hours).
4. **Report** (`recon/report.py`). One workbook with sheets Summary, Breaks, ClientMoney and AML.

Money is kept in whole ore, never in floating point.

## Measured on the demo day

Synthetic data, seed 5. The generator plants a known number of breaks of each kind and the tests check that every one is found, with the right kind.

|Measure|Value|
|-|-|
|internal trades|396|
|broker rows (including duplicates)|398|
|matched cleanly|380|
|breaks found|23 (6 quantity, 5 price, 5 missing at broker, 4 missing internal, 3 duplicate)|
|AML alerts|5 (2 large movement, 1 high risk country, 1 structuring, 1 pass through)|

## A bug the tests found in my first version

My generator planted price differences of 50 ore, but the matcher tolerates 100 ore, so two planted breaks were correctly not reported. The test that compares planted and found breaks failed (3 found against 5 planted). I changed the generator, not the tolerance, because a 50 ore rounding difference is not a break.

## Run it

```
pip install -r requirements.txt
python -m pytest -q
python -m recon demo
```

## Limits

- The data is generated by me. The AML thresholds are examples and are not legal advice. Real KYC, sanctions screening and regulatory reporting are not part of this repository.
- One day, one bank account and one broker. Settlement dates, corporate actions and currencies are not modelled.
- The next step is a KYC onboarding checklist with states and a queue of cases that wait for documents.
